# Scenes and map

## 1. Summary

- A **scene** is a map image, a grid and tokens on a react-konva canvas ([ADR-0001](../architecture/adr/0001-tech-stack.md)): the base layer of the play page ([play-shell](play-shell.md)). The DM preps scenes in the UI and can view any scene (#122); players see the one **active scene**.
- **Tokens** are instances of a creature definition ([ADR-0009](../architecture/adr/0009-entity-content-model.md)). Players never see monster definitions (#120), so a token carries its display name (instance state) and read-only copies of image and size, refreshed inside the definition edit's transaction ([FR-ENT-19](entities.md#6-functional-requirements)).
- **Feedback pass** (#145, #148; FR-MAP-31–38): token shape; speed copy + drag movement indicator; DM selection with Ctrl/Shift-click and box select, exposed to features (combat targeting); a token overlay registry for other features' token decorations (combat: out, down, target).
- **Playtest pass** (#171; FR-MAP-39–43): name **labels** in the grid gap below the token, on their own layer above every token (P2); overlays may draw a centred **cross** (combat's Down X); **live drag preview**: others see a token move while it is dragged, as a throttled signal, never logged; a hidden token's drag never reaches players; only the dragger sees the movement label (P3).
- **Polish pass** (sprint 1, R1, #178; FR-MAP-44, 45): the camera frames the scene's tokens in the **free area** (the part of the work area no window covers), when a scene opens and on a "Fit" button, so default windows no longer hide tokens.
- **Sprint 4, track V** (#243 [0], [2]; session-sim-7; owner spec-vision for these rows only, track M edits drag path and labels separately): **middle mouse pans in every tool** (FR-MAP-12); **Fit fills the canvas** while tokens stay in the free area (BL-01, FR-MAP-44); **≤ 4 Konva layers** (BL-07, FR-MAP-29); the drag sender also probes each previewed cell with `map.checkMove`, the **one drag pipeline** fog's sight preview, scene-tools' wall hint and M's drag path share (FR-MAP-39). No new FR IDs (amendments only), so M's new rows don't collide.
- **Sprint 2 phase 1** (P2b; FR-MAP-46, 47): the fit never shrinks a grid cell below a readable size (G2, decided #190, [OQ-MAP-34](#15-open-questions)); a viewport resize refits while the camera is still fitted (G3). Camera only; fog and props (phase 2) build on this canvas after it. *Seams for combat (S3):* `placeTokenIn` + `freeCellsNear` (FR-MAP-48) and a transient token `cue` (FR-MAP-49); *OQ-CBTX-24:* tokens carry a `characterId` copy players may see (FR-MAP-50).

## 2. Scope

- MVP = tier S ([feature tiers §1, §7](../feature-tiers.md#1-map-and-tokens)) plus background prep (#122). **Scene list** window: folders, create (name + map from [assets-pipeline](assets-pipeline.md)), rename, move to a folder, duplicate, delete *(proposed)*. "Show to players" activates a scene; players follow it.
- **Map and grid:** set the map; grid calibration (cell size, offset; visible, colour, opacity) with live preview; lock map; pan/zoom.
- **Tokens:** drop from the Creatures window ([entities](entities.md)); snap on drop; Large+ span several cells; labels. Owlbear-style free drag: DM moves any token, a player moves own tokens any time. Ctrl-D duplicate + rename; token art from uploads; hide/reveal; DM reassigns owner; delete. **Tools:** ruler (local), ping + DM pull view, laser pointer (right-drag off a token).
- **Feedback pass (tier S):** token shape round / square / none; movement indicator while dragging (vs speed; in combat vs movement used this turn); DM selection (click, Ctrl/Shift-click, box) + selection / targeting API for features; token overlay registry.
- **Playtest pass (tier S, #171):** label layer and label position; overlay `cross`; drag preview signal `map.drag` (sender, receivers, server routing).
- **Polish pass (sprint 1, R1):** camera fit to the free area on scene open; tool-rail "Fit" control. Client only.
- **Sprint 2 phase 1 (G2, G3):** fit floor (decided #190, OQ-MAP-34); refit on viewport resize while fitted. Client only.

## 3. Goals

- The DM preps the town and the battlemap (upload, calibrate, place, hide) entirely in the UI, while players watch another scene. Later layers and token windows plug in without changing scene or token code.
- **Zero leakage:** no player frame reveals a hidden token, a non-active scene, a folder, a scene name or a monster definition id; image IDs reach players only on records they see ([FR-ASSET-12](assets-pipeline.md#6-functional-requirements)). A drop reaches other clients ≤ 1 s after commit *(proposed)*. Positions, hidden flags and the active scene survive a hard kill ([ADR-0006](../architecture/adr/0006-persistence.md)).

## 4. Non-goals

- Fog, AoE props, layers UI, walls, HP rings, condition icons (→ [scene-tools](scene-tools.md)); current-turn highlight, path measurement, keyboard shortcuts other than Ctrl-D (tier B); token art library (tier A); location ↔ scene ([world-builder](post-mvp/world-builder.md)).
- Per-token size or stat editing (#120); ~~live drag preview~~ (in scope since #171, FR-MAP-39–41); shared ruler, a movement label for others (#171), rotation, lighting, freehand, touch ([ADR-0007](../architecture/adr/0007-product-scope.md)); undo ([ADR-0016](../architecture/adr/0016-domain-events-pending-actions.md)); server-side signal rate limit (post-MVP).
- Group move of a selection, dragging images / props onto the map (tier A, #148); movement blocking or server speed checks (indicators only, #145); player selection or targeting (#134).

## 5. User stories

- **DM:** As the DM, I want to prep the battlemap with enemies hidden while players are still in town, reveal them with one click, and pull everyone's view to a spot, so that the ambush lands.
- **Player:** As a player, I want to land on the map, drag my own token, measure, ping and laser-point, so that I can play my turn and show what I mean.

## 11. Edge cases & failure modes

- *(Sprint 4)* **Middle pan edge cases:** button 1 released outside the canvas ends the pan (window-level `mouseup`); a middle press over a window or the rail does nothing on the map; disconnect mid-pan: the pan continues (camera only). **Drag probe:** an ack arriving after the drop is stale and dropped; disconnect mid-drag → the drag snaps back (FR-MAP-28) and the probe clears; crash → `checkMove` never wrote anything.

- **Player disconnect / reconnect:** last view + banner; a drag in progress snaps back unsent. Reconnect → snapshot; scene switched meanwhile → the player lands on the new scene. **DM disconnect / reconnect:** players unaffected. Viewed scene kept if it still exists, else FR-MAP-08 default. A campaign switch resets it.
- **Server crash mid-action:** uncommitted → no event, no `ack`; the overlay drops on the snapshot. Committed → in the snapshot. A definition edit and its token refresh commit together or not at all; so do a move and its hook rows (FR-MAP-38). Signals in flight are lost (accepted). Selection and targeting are client memory: a reload clears them; a reconnect snapshot keeps the selection minus ids no longer in the store.
- **Concurrent edits:** last commit wins (DM and player move one token; two DM tabs set the grid). Token hidden mid-drag → it disappears for the player; the move → `not_found`. Owner changed mid-drag → `forbidden`, revert. Scene deleted while another DM tab views it → FR-MAP-08 default. Character renamed or re-owned → tokens keep name and owner; the DM edits them. Recalibration or a size increase may leave tokens off the map: still rendered and draggable. **Scene switch while a player loads:** the resync replaces the store; stale image loads are dropped, a 404 for the old map is ignored.
- **Invalid / malicious input:** strict zod; IDs of another campaign → `not_found`; names rendered as text; spoofed `from` ignored (server stamps it); `shape` outside the enum → `invalid`; a player sending `speed` or `shape` anywhere → `invalid` (not in their schemas). Players see `cause TokenHidden` on a hide, so they can tell a token was hidden (accepted). *(OQ-CBTX-24)* A character token's `characterId` tells players which PC it shows (they already see that PC's redacted `entity` and its name on the token: nothing new); no player token carries `definitionId`, so renamed monsters stay unlinkable. A player or DM sending `characterId` → `invalid` (server-written copy).
- **Feedback pass:** a selected token that is deleted or leaves the viewed scene drops out; one revealed or hidden stays selected (DM sees both). Speed edited mid-drag: the label uses the store value at render. Owner reassigned → that player gains or loses the token's `speed` with the upsert. Combat's `movedFt` arriving after a drop updates the next drag's label.
- **Drag preview (#171), what others see:**

| Case | Others see |
|---|---|
| Drop accepted | `TokenMoved` puts T on the dropped cell and clears the preview; the `end` that follows finds nothing to clear |
| Drop rejected (`forbidden`, `not_found`, `invalid`) | Dragger: revert + Toast (FR-MAP-15). Others: `end` clears the preview, T back on its stored cell; no event |
| Cancel (Esc; not live) | `end` (if sent) or the 3 s timeout → T back on its stored cell |
| Dragger disconnects or crashes mid-drag | No more frames → 3 s timeout → T back on its stored cell (no move committed) |
| Receiver disconnects | Its snapshot on reconnect drops every preview |
| Server crash | Signals lost; reconnect snapshot drops previews; nothing was persisted |
| Token hidden mid-drag | Players get the `delete`, preview gone with T; further frames route DM-only (FR-MAP-41). Reveal mid-drag → frames reach players again |
| DM and owner drag T at once | Each receiver shows the latest frame; each dragger ignores the other's; last committed move wins |
| Two DM tabs, one prepping a non-active scene | The other DM tab previews it if it views that scene; players never get the frames (`"dm"`) |

- **Fit (R1):** a window the user opens or moves later may cover tokens; the camera never jumps on its own then (Fit fixes it). Disconnect / reconnect: no refit (same scene), unless a window first appears in the reconnect snapshot while the camera is `fitted` (e.g. a player offline at Start gets Initiative: one refit); a reload refits. Server crash: camera unaffected; the rejoin snapshot refits only under that same rule. A player's fit only uses tokens in their store, so it reveals nothing hidden. Free area too small (many windows): fit into the work area (FR-SHELL-34). One token: today's zoom, centred on it in the free area.
- **Floor and resize (G2, G3):** the floor may leave monsters under a window; PC tokens get priority, and a player's store never holds hidden tokens, so nothing hidden is revealed or hinted. Resize mid-drag: the refit waits until the drop or cancel (camera untouched during a drag). Resize while not `live`: refits (camera only, FR-MAP-28). Disconnect / reconnect / crash: no change from R1; the camera is client memory, a reload fits afresh.

## 12. Performance & bandwidth

- Moves are drop-only: ≤ a few intents/s, ≤ 400 B per event. Drag preview (#171): ≤ 20 frames/s × ≈ 150 B per dragger ≈ 3 KB/s per receiver, ≈ 18 KB/s fan-out to 6 players over the tunnel; one indexed token read per frame on the server (FR-MAP-41). Labels layer: one text node + pill per token (≤ 200), no extra network. Previews live in their own store and redraw only the previewed token's group and label (FR-MAP-40). **Review check:** Chrome trace on the DM client while `player-1` drags on Cellar: median frame ≤ 20 ms. Laser ≤ 20 frames/s × ≤ 600 B per sender ≈ 72 KB/s fan-out to 6 players over the tunnel ([ADR-0003](../architecture/adr/0003-local-hosting.md)). Map `display` ≤ 4096 px, 1–3 MB once per browser ([assets-pipeline §12](assets-pipeline.md#12-performance--bandwidth)).
- *(Sprint 4, measured, [FOG §12](fog-of-war.md#12-performance--bandwidth))* `map.drag` frame 243 B (≤ 20 / s, unchanged). The drag probe adds ≤ 10 `map.checkMove` / s per dragger (one in flight; ≈ 60 B out); its ack with a sight hint is 651 B typical, 10,598 B at caps, to the dragger only. Middle-mouse pan and the layer grouping send nothing; four Konva layers instead of 6–9 (fewer canvases to composite per frame).
- Feedback pass: overlay fns run per token per render (≤ 200 tokens, O(1) store lookups); box select is one pass over the scene's tokens; a move adds one indexed lookup per hook (combat: `combatant.tokenId`) and, in combat, one ≤ 300 B `combatant` upsert. Token +2 fields ≈ +20 B.
- Snapshot: token ≈ 300 B, scene ≈ 400 B; 30 scenes × 30 tokens ≈ 280 KB. Shared DM budget: scenes ≤ 300 KB of live-sync's 512 KB (1,000-token cap). Players get one scene. **Review check:** Chrome trace of a 10 s pan on Cellar (4096 px map, grid on): median frame ≤ 20 ms.
