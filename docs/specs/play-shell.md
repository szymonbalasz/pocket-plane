## 1. Summary

- The one play page per client (Roll20-style): scene canvas as the base, **floating windows** over it ([ADR-0014](../architecture/adr/0014-mvp-scope.md), [decisions-log](../decisions-log.md) #44, #48). Replaces the DM's six-window setup ([vision](../vision.md#the-table-today)).
- Features don't own pages: they register **window types**; the shell opens, arranges and persists them. Plug-in contract: [ADR-0025](../architecture/adr/0025-play-shell-windows.md).
- **Layout** lives in browser storage, per campaign and owner (DM or the link's player); it never reaches the server (#121).
- Hosts the foundation UI: connection indicator, reconnect banner, presence ([live-sync](live-sync.md)); switcher, players panel, login / waiting / invalid-link screens ([campaign-management](campaign-management.md)).
- **Feedback pass** (F1, #148; [ADR-0030](../architecture/adr/0030-ui-notification-sounds.md)): an **alert** surface for features (screen flash + short UI sound + Toast); first caller: combat's player turn alert ([FR-CBT-41](combat-tracker.md#6-functional-requirements)). Per-browser mute + volume.
- **Playtest pass** (#171; FR-SHELL-29–33): one shared **tooltip** delay (≈ 400 ms) and no tooltip fighting a popover (P1); windows **fit the work area** on smaller viewports (G3); the DM's Initiative default shows a full encounter (G2); presence reads "unknown" while the DM is not live (G10).
- **Polish pass** (sprint 1; FR-SHELL-34, 35): the shell reports the **free area** (work area no window covers) so the map can frame tokens there (R1, #178); the DM's Game log shows a real history at default size (R3).
- **Sprint 2 phase 1** (P2b, N1; FR-SHELL-36–38, decided #190, [OQ-SHELL-21](#15-open-questions)): minimise gets a meaning of its own. A minimised window is **parked**: it stays alive (scroll, tab, drafts kept), its launcher button looks different from an open one, and a dot shows when something new happened in it. Close stays "gone".
- **Sprint 4** (FR-SHELL-40–44): windows that open **by themselves** go where they cover the fewest tokens, and a feature never opens one on top of another (FR-SHELL-40, 41); target-less windows (the handout viewer) don't come back after a reload (FR-SHELL-42); the launcher fits any viewport ≥ 1280 px (FR-SHELL-43); the shell offers every free rectangle so the map picks the one its tokens fit (FR-SHELL-44 → [FR-MAP-58](scenes-map.md#6-functional-requirements)). Browser-only, 0 bytes.
- **Sprint 5** (FR-SHELL-45–54): the screen has **zones**: right column = Initiative (DM) / sheet (player), bottom strip = a **wide Game log**, toasts and roll popups where they are today (players: bottom-right **toast corner**; DM: **top-centre**, #256), top strip right of the tool rail = the active **tool bar**, which pushes windows off it (FR-SHELL-55), the rest = map. Windows the user opens go to a clear spot (edges first, then beside an edge window, #256 amending #162), never on a window or a keep-out region while one exists; when the screen is full the least recently used launcher window is auto-minimised. The fit keeps every token visible ([FR-MAP-59](scenes-map.md#6-functional-requirements)). Browser-only, 0 bytes.

## 2. Scope

- Page frame for DM and player clients: base layer, top bar, tool rail slot, launcher, banner, toast region. Window manager: open, close, move, resize, bring to front, minimise; clamp to viewport; reset layout *(proposed)*.
- Window registry (client code) and `openWindow(kind, instance?)` for features; `instance` key ready for several windows of one type (tokens open notes later, ADR-0014), MVP uses `main` only.
- **Alerts** (FR-SHELL-22–27): `alert()` API, flash, built-in ping, player sound control (mute, volume), audio unlock on first interaction, test-mode hooks.
- **Playtest pass** (FR-SHELL-29–33): shared Tooltip rules for both clients; render-time fit of windows to the work area; DM Initiative default height; presence badge while not live.
- **Polish pass** (FR-SHELL-34, 35): free-area helper for the canvas; Game log history numbers at default size. No new window, default geometry or stored field.
- **Sprint 2 phase 1** (FR-SHELL-36–38, decided #190, OQ-SHELL-21): minimised windows stay mounted; distinct launcher states; optional per-window-type `activity` for a "new" dot; *(S2)* opt-in `growToContent` (FR-SHELL-39). No new window or default geometry; `WindowState` gains only optional `fixedH`.
- **Sprint 4** (FR-SHELL-40–44): token-aware auto placement; feature-driven opens re-placed off other windows; `restoreOpen` on window types; launcher compaction + overflow menu; candidate free rectangles. No new stored field; `WindowDef` gains optional `restoreOpen`; `openWindow` gains an optional `by`.
- **Sprint 5** (FR-SHELL-45–54): placement rank fix, inward columns, screen-full fallback, keep-out regions (toast regions + tool bar), toast boxes sized for the 320 × 190 popup, tool bars pushing windows aside, named default layouts with viewport-dependent sizes, growth cap, old-default migration, re-baselined coverage floors. `WindowDef` gains optional `defaultSize` function and `previousDefaults`; nothing stored or sent changes. Out: window contents (Creatures names cut to "G…" in a narrow window, sim-8 j: entities), the combat apply popup's spot (combat-tracker, track R).
- **Later, not built** (nothing here may block them): command palette, shortcuts, portrait strip, pause overlay, DM "view as player". They plug in via the registry, a reserved strip slot above the launcher and an overlay layer.

## 3. Goals

- Everything used during play is reachable without leaving the canvas; a player sees the active scene with no clicks after opening the link.
- Each owner's arrangement survives reload, reconnect and a server or browser crash. A feature adds a window by registering it, no shell code changes. Layouts never leave the browser; opening a window grants no data.

## 4. Non-goals

- BG2 styling, portrait strip (→ [theme-system](post-mvp/theme-system.md)); mobile/touch ([ADR-0007](../architecture/adr/0007-product-scope.md)); docked panels; pop-out browser windows; restoring a layout on another browser (#121).
- Window contents (each owning spec); canvas behaviour ([scenes-map](scenes-map.md)).
- Music, ambience, soundboard, voice ([ADR-0007](../architecture/adr/0007-product-scope.md), [ADR-0030](../architecture/adr/0030-ui-notification-sounds.md)); DM-added sounds (tier A, design for later, FR-SHELL-26); OS / push notifications; a DM sound control (no DM alerts in MVP).

## 5. User stories

- **DM:** I want the players panel, scene list and (later) initiative as windows over the map, so that I run the session from one tab; and my arrangement back after a crash, so that I don't rebuild it mid-session.
- **Player:** I want to land on the map the DM is showing, so that I'm in the game the moment I open my link; and my windows where I left them.
- **Player:** I want the screen to flash and ping when something needs me (my turn), and to mute or turn it down, so that I don't miss it and it doesn't annoy the table.
- *(Sprint 4)* **DM:** When combat starts I want Initiative to open where it doesn't hide the goblins I'm about to target, and never on top of the window I'm reading. **Both:** on a 1280-wide laptop I want every launcher button reachable and the tokens I can see out from under my windows.
- *(Sprint 5)* **DM:** When I open Compendium, Party and Encounters during a fight, I want each one where I can read it, not stacked on the last one or on my Game log; and a Game log wide enough that a damage line fits on one line. My roll popups and combat cards should not sit on the monsters at the top of the map. **Player:** On my laptop I want my sheet, Initiative and the AoE panel side by side with the map, not on top of each other or of the monsters.

## 8. Data model

No server entity, record type or migration (#121). Client-side only:

| Entity | Field | Type | Notes |
|---|---|---|---|
| Layout *(browser `localStorage`)* | key | `pp.layout.v1.<campaignId>.<dm \| playerId>` | One per (origin, campaign, owner); no secret token in the key |
| | windows | WindowState[] | zod-parsed on read (FR-SHELL-17); ≤ ~4 KB |
| WindowState *(in `windows`)* | kind, instance, state, x, y, w, h, z | string, string (`main`), `open` \| `minimised` \| `closed`, int ×5 | px from viewport top-left; z = stacking order |
| | area *(#171)* | `{w, h}` int, optional | Work area when this window's geometry was last set (FR-SHELL-29) |
| | fixedH *(S2)* | `true`, optional | Set at a user resize end on a `growToContent` window (FR-SHELL-39); absent = grows; older entries still parse |
| Window type *(client code)* | FR-SHELL-07 fields; *(N1)* `activity?(store)`; *(sprint 4)* `restoreOpen?: false`; *(sprint 5)* `defaultSize: Size \| (vp) => Size`, `previousDefaults?: Size[]` | — | Per-client registry; not sent or stored (FR-SHELL-38, -42, -48, -51, -53) |

- **Relations:** key names a Campaign and Player ([campaign-management](campaign-management.md)) by ID only; kinds name window types, not records. **Derived:** rendered geometry = clamp(fit(stored, area, work area), viewport) (FR-SHELL-29, -12); launcher states; presence known iff `live`; *(R1)* free area from the rendered rects, appearance counter (FR-SHELL-34); *(N1)* activity value at minimise + dot, client memory only (FR-SHELL-38); *(sprint 4)* placement scores, candidate free rectangles, launcher compaction (client memory, recomputed). ## 11. Edge cases & failure modes

- **Player / DM disconnect / reconnect:** last view + banner; windows still movable and written; players unaffected by DM drops. Snapshots don't move windows (FR-SHELL-16).
- **Campaign switch:** DM restores the new campaign's DM entry (default if none); players get the waiting screen, then the shell as it was.
- **Server crash:** layout unaffected (browser-side). **Browser crash:** every finished change was already written; a drag in progress is lost.
- **Another browser, fresh profile, or new origin** (dev vs verify port, new tunnel URL): separate storage → default layout. Accepted (#121).
- **Two tabs, same owner:** last write wins, no live jumps (FR-SHELL-19). **Two players on one browser** (different links): separate keys.
- **Viewport change:** clamp, render-only (FR-SHELL-12). **Removed or unavailable window type:** FR-SHELL-18. **Corrupt or full storage:** FR-SHELL-17.
- **Shared computer:** entries hold only window geometry and kinds, no game data.
- **Playtest pass:** viewport shrinks mid-session → windows refit at once, render-only; a drag / resize in progress is refit at pointer up. Layout from a bigger screen opened on a laptop → fits; reopened on the big screen → as stored. Tooltip pending when the connection drops: unaffected (client only). Presence: disconnect → "unknown" at once; reconnect → snapshot presence; server crash → "unknown" until rejoin (no stale "2/2 online").
- **Polish pass:** free area is recomputed from what is rendered (viewport resize, window moves); only the canvas decides when to use it (FR-MAP-44). Every window minimised → the work area. Disconnect / reconnect / crash: client-only geometry, unaffected; snapshots never open, close or move windows (FR-SHELL-16); a kind that first becomes available in a reconnect snapshot counts as one appearance (FR-SHELL-34).
- **Minimised (N1):** reload or a browser crash → the window comes back minimised and mounted fresh (its unsaved state is lost, like any reload); the dot baseline is taken after the first snapshot, so nothing old lights it. Disconnect / reconnect: the window stays mounted; a reconnect snapshot that changes `activity` (e.g. log entries made while offline) lights the dot: there is news. Server crash: same as reconnect. Snapshots never minimise, restore or close windows (FR-SHELL-16). Two tabs: dots are per page.
- **Sprint 4 (placement, launcher):**
  - Disconnect / reconnect: snapshots never open, close or move windows (FR-SHELL-16); a kind that first becomes available in a reconnect snapshot is an appearance and is auto-placed (FR-SHELL-40), scored on the tokens drawn after that snapshot. Server crash: same as reconnect; nothing server-side.
  - Reload: the default layout and stored spots apply as before; `restoreOpen: false` windows load closed; auto placement scores 0 until the canvas has drawn tokens (first load), so the default rect wins and the camera fit frames the tokens around it.
  - Two tabs, same owner: auto-placed rects are written like any change (last write wins, FR-SHELL-19).
  - No candidate free of other windows: today's cascade (protocol §18), still least token cover first. All candidates cover tokens equally (e.g. at the 48-px floor on 1280×720): today's order.
  - Viewport shrinks mid-session: the launcher recompacts at once; windows fit per FR-SHELL-29 (render-only; no re-placement).
- **Sprint 5 (windows, keep-outs, toast regions, tool bar push):**
  - Disconnect / reconnect: snapshots never open, close, move or auto-minimise windows (FR-SHELL-16); an appearance in a reconnect snapshot is auto-placed by FR-SHELL-45 with the keep-outs of that moment; toasts and popups keep their regions. Server crash: same as reconnect; nothing server-side.
  - Reload: stored layout as before (auto-minimised windows load `minimised`, no `data-auto-minimised`); default-sized windows follow the viewport (FR-SHELL-53); the tool bar re-reports after the first canvas render, so an auto placement before that sees only the toast box; a tool bar shown after a reload pushes again (FR-SHELL-55).
  - Viewport resize mid-session: windows fit render-only (FR-SHELL-29), nothing re-placed or auto-minimised; the toast boxes and the tool bar follow the viewport; a tool bar that grows (wraps) on a smaller viewport pushes again. A layout stored on a bigger screen may render windows over each other on a smaller one (render-only fit, accepted as today; Reset layout gives the named layout).
  - Screen full with only protected windows open (e.g. 1280×720 with the DM's Initiative grown by the user): FR-SHELL-45's last resort; nothing is auto-minimised that the user can't restore from the launcher.
  - Two tabs: auto-minimising and placement are per page; writes last-write-wins (FR-SHELL-19).
  - A keep-out the user moved a window onto: kept (user's choice); only auto placement avoids it.
- **Alerts:** audio still locked (no interaction yet) → flash + Toast only; the speaker shows `locked`. Two tabs of one player → both alert and play (accepted). Tab hidden → title mark (FR-SHELL-23); the sound plays if unlocked. Disconnect / reconnect: alerts come only from live events, so nothing replays on a snapshot (callers' rule, e.g. FR-CBT-41). Server crash: no effect on settings. Corrupt or missing sound settings → defaults.
